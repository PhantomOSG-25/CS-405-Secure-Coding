# Week 3: Security Policy Milestone

The Week 3 folder contained `CS 405 Security Policy.docx`, the working Green Pace secure development policy used for the Module Three milestone.

## Work Completed at This Stage

The milestone established the foundation that was later expanded into Project One.

### Ten Core Security Principles

1. Validate Input Data
2. Heed Compiler Warnings
3. Architect and Design for Security Policies
4. Keep It Simple
5. Default Deny
6. Adhere to the Principle of Least Privilege
7. Sanitize Data Sent to Other Systems
8. Practice Defense in Depth
9. Use Effective Quality Assurance Techniques
10. Adopt a Secure Coding Standard

### Ten C/C++ Coding Standards

The milestone document contained working policy sections and compliant/noncompliant examples for:

- STD-001: Use the correct data type
- STD-002: Validate numeric values before use
- STD-003: Validate string length before use
- STD-004: Prevent SQL injection
- STD-005: Memory protection
- STD-006: Assertions
- STD-007: Exception handling
- STD-008: Numeric overflow
- STD-009: Variable initialization
- STD-010: Hard-coded secrets

The document also contained the Project One sections that would be completed later, including threat assessment, automated detection, DevSecOps automation, encryption, Triple-A, audit controls, enforcement, exceptions, distribution, and policy change control.

## Progression Into Project One

This Week 3 document is an earlier milestone version. The fully completed Green Pace policy is documented under [`projects/project-one/`](../../projects/project-one/), where the standards were expanded with principle mappings, risk ratings, automated detection tools, encryption policies, Triple-A policies, DevSecOps guidance, and final recommendations.
